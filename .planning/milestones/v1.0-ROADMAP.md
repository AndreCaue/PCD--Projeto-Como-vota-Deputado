**Status:** ✅ SHIPPED

## Milestone Summary

Full QSA (Quadro de Sócios e Administradores) integration module for cross-referencing Brazilian Federal Deputies with Receita Federal company data (100% offline). Includes automatic ingestion, CPF and fuzzy spouse-name matching, graduated conflict of interest detection, and API exposure with freshness tracking.

---

## Phases

### Phase 1: Foundation — Data Ingestion and Matching (2 plans)

**Goal:** Establish foundational data pipeline for ingesting QSA data and matching deputies to companies via exact CPF and dual strategy matching.

**Requirements:** ING-01, ING-02, ING-03, MAT-01, MAT-03, MAT-04, API-01, API-03, INF-01, INF-03, DQ-02, DQ-03

**Plans:**
- **01:** Test Suite — 50 test cases across 5 test files covering ingestion, matching, API, CNPJ validation, and database
- **02:** Data Ingestion & Matching — QSA download pipeline, chunked CSV processing, exact CPF + fuzzy name matching via rapidfuzz, API endpoints

### Phase 2: Enhancement — Matching Refinement and Data Quality (4 plans)

**Goal:** Improve matching accuracy with spouse name fuzzy matching and enhance data quality with incremental processing and freshness tracking.

**Requirements:** MAT-02, CONF-03, CONF-04, API-02, API-04, INF-02, INF-04, DQ-01, DQ-04

**Plans:**
- **01:** Data Model + Schema Migration + Test Infrastructure — alta_exposicao/via_conjuge columns, QsaMetadata, Config model, idempotent migration
- **02:** Service Layer — confidence score bug fix, alta_exposicao/via_conjuge flag computation
- **03:** Data Pipeline — incremental import with upsert, freshness tracking, GET /qsa/freshness
- **04:** API Endpoints — GET /deputados/empresas paginated listing, inline freshness, incremental trigger

### Phase 3: Intelligence — Conflict Detection and UX (4 plans)

**Goal:** Detect potential conflicts of interest through graduated conflict scoring and exposure flags.

**Requirements:** CONF-01, CONF-02

**Plans:**
- **01:** Data Model Extensions — CNAE columns, EmpresaCnaeSecundario, conflict flags on Relacao, migration
- **02:** CNAE Import Pipeline — CNAE field capture in both import paths, secondary CNAE parsing, config seed
- **03:** Conflict Detection Service — 3-factor graduated scoring (50/30/20), CNAE matching, response serialization
- **04:** API Updates — refined tem_conflito filter, conflito_interesse query param, total_conflito, tests

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Boolean relationship_type (False=CPF, True=nome_match) | Simple, queryable | ✓ Good |
| rapidfuzz fuzzy name matching (threshold 75) | Lightweight, efficient | ✓ Good |
| Chunked CSV processing (10k rows) | Memory constraint for millions of CNPJ records | ✓ Good |
| Idempotent DDL migration via PRAGMA guards | Re-runnable without errors | ✓ Good |
| Incremental upsert via sqlalchemy on_conflict_do_update | ORM-safe, injection-free | ✓ Good |
| 3-factor scoring: capital(50) + CNAE(30) + CPF(20) | Simple graduated model | ✓ Good |
| Inline freshness in API responses | No separate endpoint needed | ✓ Good |
